## v5.5 設計原則

### 1. Talent-Skill separation（Stage 67 起）

- **Talent** = 人物 identity（Victoria / Petra / Cody / Vera / Quinn / Sage）+ persona prompt（`talent_prompts.PersonaBody`）
- **Skill** = 能力 capability（`code_implementation` / `code_review` / `qa_testing` / `documentation` / `petra_orchestration` / `ceo_orchestration`）+ skill prompt（`skill_prompts.PromptBody`）
- **Talent 可兼多 Skill**（如 Cody = code_implementation + ui_design + release_publishing 三 skill）
- **Skill 動態 dispatch**——Petra 依 task 拍板派 Talent + Skill / 不是寫死 1:1 mapping

### 2. Petra 動態 orchestrator（Stage 63B PoC / Stage 64 路線 D 採用）

- **Petra 純 LLM API call**——不用 Claude Code CLI / 不動 codebase（業界 supervisor 紀律 — 對齊 LangGraph / Databricks / Claude Agent SDK 共識，Trial_v26 WebSearch 驗證）
- **Petra 3 call sites**（`PetraOrchestratorService.cs:227/407/474`）：
  1. `DecideCapabilityAsync` — 看 task 決定 capability sequence
  2. `DecideSkillsAsync` — 對齊 Skill registry pick Skill
  3. `DecideSubtaskPlanAsync` — 拆 SubtaskPlan JSON
- **Petra 4 call site**（Stage 81）：`InvokePetraReplanAsync` — Vera critical 後給 retry instruction
- **Provider 切換**：DB SoT `agent_configs.Provider/Model`（Dashboard 動態調 / Stage 38 起）
  - 當前 production active：**Anthropic / claude-sonnet-4-6**（Stage 82 後 Christ 拍板 — reliability > cost）
  - 過去 default：Gemini Flash（Trial_v6-v25 / Stage 82 前）— Trial_v25 揭 503 transient + Haiku conversational preamble 議題後切

### 3. HITL（Human-in-the-Loop）兜底紀律

對齊業界 supervisor pattern 三層分工（Trial_v26 WebSearch 驗證）：

- **Stage 80** — HITL `plan_confirm` 閘門：Petra 拆完 plan 後 pause + 開卡給 Christ 4 button（核准 / 修改 / 不採納 / 補充）
- **Stage 81** — 動態 re-planning + HITL `replan_confirm` 閘門：Vera 標 critical 後 `DetectReplanTrigger` fire → Petra 給 retry instruction → 開卡給 Christ 同 4 button
- **Stage 81** — max iterations + cost cap intervention：防 replan 死循環 / Workflow:MaxReplanIterations=3 + ReplanCostCapUsd=5 default

### 4. Worker 用 Claude Code CLI subprocess

- **Adapter**：`ClaudeCodeChatClientAdapter` 包 `IClaudeCodeService` 為 IChatClient（Stage 63B PoC + Stage 64 路線 D）
- **Stream output**：`--output-format stream-json --verbose` + NDJSON line-by-line accumulate `type=assistant.message.content[].text`（Stage 82 修法 / 解 Quinn tool-heavy 場景 final turn tool_use → result 空 議題）
- **Session 延續**：worker 用 `--session <id>` flag + workspace 保留 → 跨 dispatch 脈絡延續
- **Skill Prompt 載入**：DB `skill_prompts` 優先 → fallback `Resources/CLAUDE_<X>.md`（Stage 72 起）/ Christ 紀律「不污染 CLAUDE_<X>.md 跨專案守則」

## 三層分工總覽

| 角色 | 用什麼 | 能做什麼 | 業界對齊 |
|---|---|---|---|
| **Petra**（指揮腦）| LLM API call（Sonnet 4.6 production active）| 看文字、拆 plan、決定誰接手、給 retry 建議 | LangGraph supervisor / Databricks orchestrator |
| **Cody / Vera / Quinn / Sage**（執行手）| Claude Code CLI subprocess | 在 workspace 跑、改 code、跑 test、開 PR | Claude Agent SDK worker / 業界「each agent only sees files it owns」紀律 |
| **Christ**（拍板者）| Dashboard 4 button | 看 Petra 建議 / 拍板要不要照做 | 業界 HITL 兜底 / 接受 LLM 局限用人類補強 |

**戰略意義**：Trial_v26 WebSearch 驗證 AiTeam v5.5 三層分工**對齊業界主流** supervisor pattern（撤回前面 Aria 推論「Petra 切 CLI」FF 候選 — 業界不推薦 / cost 5x + hallucination 風險）。

## 對話 vs 真實 chain

**Christ 派指令**（Discord / Dashboard）→ **Victoria** flag forward 寫 PetraInbox → **PetraInboxProcessor** push channel → **PetraDispatchWorker** consume → **PetraOrchestratorService** 起 PetraSession → **Petra** 拆 SubtaskPlan → （HITL plan_confirm 卡 if flag）→ **Cody/Vera/Quinn/Sage** chain dispatch（每 worker 一個 Claude Code CLI subprocess）→ （Vera critical → HITL replan_confirm 卡 if flag）→ **Cody** commit + push branch → **FinalizeGitAsync** 開 PR → 完成。

**Petra 拆 plan 規模自適應**（LLM nature）：
- 簡單 task → 2-3 subtask
- 中等複雜度 → 3-4 subtask
- review-fix cycle 需要 → 5+ subtask（含 Cody fix + Vera reverify cycle）

詳細 chain 真實流程見 [`03_Workflow_Overview.md`](../architecture/03_Workflow_Overview.md)。
